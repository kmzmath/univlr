# rAAting 3.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** trocar o rAAting 3.0 pelo rAAting 3.1 (fórmula estimada da HLTV com o dano ÷ 1,5 e 1,00 na média do grupo, swing novo, economia sem ajustes sem fonte, Regen Shield) no build, no navegador e na cópia em Python, reproduzindo o estudo de 20-21/11 com diferença de no máximo 1e-9.

**Architecture:** o núcleo (`raating-core.js`) passa a guardar a média do grupo (`setGroupCenter`) e calcula a nota como `1 + Σ β·(x − x̄)`. O `buildDatabase` mede a tabela com spike no contexto, faz as contagens, tira a média de todas as linhas, grava a média no núcleo e no `metadata.raatingContext` e só então refaz as notas e os agregados. O navegador e o `build_home` leem a média do banco antes de recalcular qualquer nota. A conferência final compara o banco novo com um oráculo gerado pelos scripts do estudo antes de qualquer mudança no código.

**Tech Stack:** JavaScript sem dependências (Node para build e testes, `node:assert`, `vm`), Python 3 (relatório), sem `npm install`.

**Spec:** `docs/superpowers/specs/2026-11-21-raating-hltv-design.md` (aprovada em 21/11/2026). Estudo: `outputs/estudo-raating-hltv-2026-11-20/RELATORIO.md`.

## Global Constraints

- Texto, código e commit em pt-BR, **nunca travessão ou meia-risca; sempre hífen**.
- β: abate 0,4941; sobrevivência 0,3795; dano 0,4280 ÷ 1,5; KAST 0,2602; swing 0,03748; multi-kill 0,0241.
- Média do grupo: soma das contagens de todas as linhas jogador x mapa do build ÷ soma dos rounds, refeita a cada build; 1,00 na média.
- Nome na tela: "rAAting 3.1"; `rating_version`: `"raa3.1"`; o campo `raating_3` mantém o nome (decisão do construtor, para não quebrar leitores).
- Economia: multiplicador `2.095 - 2.074 * p`, sem dividir pela média e sem o limite de 0,35 a 1,75.
- Regen Shield `B1B9086D-41BD-A516-5D29-E3B34A6F1644` = +50; explosão da spike em `plantRoundTime + 45000`, corte em `plantRoundTime + 45000 - 50`.
- `SAMPLE_MIN_ROUNDS` continua 50. Sem limites na nota.
- O rAAting 1.0 (`raating_1`, `impactTotalLegacy`, `kastLegacyRounds`) não muda em nenhuma linha.
- Placar (K/D/A, ADR, ACS, KAST clássico), cartinhas (`cartas/`, `ferramentas/cartinhas/`) e matérias não mudam.
- Trabalho no ramo `raating-3-1`, um commit por tarefa conferida. **Nada de push.** `database.json` e `home.json` vão juntos no mesmo commit.
